# ADR-001 · 用 RRF 替代加权归一化融合

**日期**：2026-08-07
**状态**：已采纳
**相关**：`rag/scoring.py`、`rag/retriever.py::_hybrid_search`

## 背景

混合检索需要把向量召回与 BM25 召回合成一个排序。原实现是加权相加：

```python
v_score = max(0.0, 1.0 - distance / 2.0)      # 绝对距离转换
b_score = bm25_score / max_bm25                # 相对归一化
hybrid  = 0.7 * v_score + 0.3 * b_score
```

## 问题

1. **量纲不可比**。余弦距离与 TF-IDF 得分是不同物理量，没有数学依据支持加权相加。
   任何归一化都是在强行制造可比性。
2. **相对归一化引入系统性偏差**。`score / max_score` 使本批结果里最好的那条
   恒得 1.0 —— 即使它完全不相关。查询在知识库中无答案时，BM25 侧仍会贡献一个满分。
3. **权重参数无意义**。既然两侧尺度不可比，`0.7 / 0.3` 无法通过任何原理推导，
   调参也无法解释。

## 决策

采用 RRF（Reciprocal Rank Fusion，Cormack et al. 2009, SIGIR）：

```
score(d) = Σ_i  1 / (k + rank_i(d)),  k = 60
```

只使用排名，不使用分数。

## 理由

- BM25 原始分是 3.7 还是 3700 不影响结果，只看它排第几 —— 归一化问题、
  权重调参问题、尺度不可比问题一次性全部消除。
- `k=60` 压平头部差距：k=0 时第 1 名 1.0、第 2 名 0.5，头部权重过大；
  k=60 时两者 0.0164 与 0.0161。这使"两路都排中游"能胜过
  "一路第一、另一路缺席"，正是融合想要的语义。
- 工业界混合检索的默认方案（Elasticsearch、Vespa、Weaviate 均内置）。

## 代价

- RRF 分数没有相关性语义（量级 0.016~0.033），不能展示给用户，
  也不能用于阈值判断。因此必须另有一条相关性口径。
- 无法表达"向量比 BM25 更重要"这类先验。若将来确有需要，
  可在 RRF 内对某一路乘系数，但那会重新引入不可解释的参数，
  应先用评测集证明确有收益。

## 配套设计

排序与展示彻底分离，两个函数职责不可混用：

| 函数 | 用途 | 值域 | 可展示 |
|---|---|---|---|
| `rrf_fuse()` | 排序 | 约 0.016~0.033 | 否 |
| `compute_relevance()` | 展示、阈值 | [0,1] 越大越相关 | 是 |

`compute_relevance()` 的两条映射都有物理依据：

- **有 rerank logit** → `sigmoid(logit)`。bge-reranker 以二分类交叉熵训练，
  logit 过 sigmoid 后就是模型自身估计的"这对 query-doc 相关"的概率。
  这不是自造映射，是模型原生语义。
- **无 rerank** → `1 - cosine_distance / 2`。归一化向量的余弦距离 ∈ [0,2]，
  线性映到 [1,0]。

前端仪表盘据此标注口径（"精排相关概率" / "余弦相似度"），
不再展示一个不知道量纲的百分比。

## 验证

`tests/test_scoring.py::TestRRFFuse` 覆盖：得分公式、两路累加、
共识胜过单路第一、BM25 尺度无关性、同路重复只计一次、k 校验、k 与头部差距的关系。
`TestSeparationOfConcerns` 断言 RRF 分数不可当相关性使用。
