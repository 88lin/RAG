# 检索方案评测报告

**日期**：2026-08-07
**数据集**：T2Ranking（THUIR，中文真实搜索日志 + 人工相关性标注）
**结论摘要**：

1. 换中文 embedding 模型使 Recall@5 从 0.023 提升到 0.707（约 30 倍）
2. RRF 在本数据集上未带来增益（0.708 vs 0.707），延迟涨 3.5 倍
3. Rerank 质量增益一致（MRR@10 0.947，最高）但 CPU 延迟 9.8 秒不可线上
4. **单一 relevance 阈值无法判定可答性** —— 有答案与无答案的
   top1 分布严重重叠（无答案最小值 0.714 高于有答案最小值 0.697）

## 1. 实验设置

| 项 | 值 |
|---|---|
| 评测 query | 300 条（从 22,812 条带标注 query 中随机抽样，seed=42） |
| 语料规模 | 13,536 段（1,504 gold + 12,032 干扰，干扰倍数 8） |
| 每 query 平均 gold | 5.0（范围 1–23） |
| 召回候选数 | 20（指标按 k 截断在计算阶段做） |
| 向量库 | ChromaDB，余弦距离 |
| 硬件 | 单机 CPU（无 GPU） |
| LLM | 未参与检索层评测 |

**语料构建方式**：`collection.tsv` 全量 3.5GB 未下载全部段落入库。
先由 qrels 确定 300 条 query 的全部 gold pid（1,504 个），
再流式扫描 collection 用 reservoir sampling 抽 8 倍干扰段落。
gold 命中率 1504/1504，无缺失。

**与生产路径的差异**（故意为之）：
1. 不做相关性阈值过滤 —— 否则 Recall 被阈值间接决定，
   无法区分"检索差"与"阈值严"。
2. 固定召回 20 条 —— 一次检索可算 Recall@1/5/10，不必为每个 k 重跑。

## 3. 换 embedding 模型的收益

**Recall@5 从 0.023 提升到 0.707，约 30 倍。**

`all-MiniLM-L6-v2` 是英文模型，在中文语料上 Recall@1 仅 0.011、
MRR@10 仅 0.058 —— 基本等同于随机排序。这与 M0 阶段在 59 chunk
小语料上的观察一致（当时表现为"top1 总是返回同一个文档"）。

唯一变量就是模型：两个 variant 用同一份语料、同一套分块、
同样的检索流程与召回数。

**这是整个项目单点收益最高的一次改动。** 值得注意的是，
在此之前项目的多处"优化"（Multi-Query 扩展、Query Rewrite、
短查询注入 jieba 实体）都是在给一个失效的 encoder 打补丁，
换模型后这些补丁的必要性需要重新评估。

bge 系列的查询侧指令前缀是必要条件：查询与文档编码同一句话的
余弦相似度为 0.887（若接近 1.0 说明前缀未生效，收益会大幅下降）。

## 4. RRF 相比单路的增益：本数据集上无增益

| 方案 | R@5 | P50 ms |
|---|---|---|
| vector_bge | 0.707 | 15.1 |
| bm25 | 0.586 | 42.5 |
| rrf | 0.708 | 52.1 |

RRF 的 Recall@5 是 0.708，纯向量是 0.707 —— 差异在噪声范围内，
而延迟从 15ms 涨到 52ms（3.5 倍）。nDCG@10 甚至略降（0.837 vs 0.854）。

**这是一个诚实的负面结果。** 原因是 T2Ranking 的 query 来自真实搜索日志，
以语义匹配为主（如"博士蛙童装怎么没有了"、"电脑只能访问网关不能访问目标主机"），
关键词精确匹配类查询占比低。BM25 单独只有 0.586，对已经达到 0.707 的
向量路提供不了有效补充。

**这不否定 RRF 的价值，但限定了它的适用条件**：混合检索的收益来自
两路的互补性。当一路显著弱于另一路且没有独特覆盖时，融合只增加延迟。

需要 BM25 的场景是编号、型号、专有名词类查询（如"EV Ban 通告编号"、
"Rider Clauses 附加条款"）—— 这类 query 在垂直领域知识库中占比更高。
后续应当在 query 类型上分层报告，而不是只看总体均值。

关于 RRF 的实现选择（为何不用加权归一化）见
[ADR-001](../decisions/ADR-001-rrf-over-weighted-fusion.md)。

## 5. Rerank 的增益与代价

| 指标 | rrf | rrf_rerank | 变化 |
|---|---|---|---|
| Recall@5 | 0.708 | 0.747 | +5.5% |
| MRR@10 | 0.902 | 0.947 | +5.0% |
| nDCG@10 | 0.837 | 0.900 | +7.5% |
| P50 延迟 | 52 ms | 9842 ms | **189 倍** |

质量增益真实且一致：三个指标同向提升，MRR@10 达到 0.947 是全部方案中最高的。
nDCG 提升幅度（+7.5%）大于 Recall（+5.5%），说明 rerank 主要贡献是
**把已召回的正确文档排到更前面**，而非召回更多 —— 这与 cross-encoder
的作用机制一致（它只对候选重排，不改变候选集）。

**但 P50 延迟 9.8 秒，其中 rerank 阶段占 11.2 秒（均值）。**
cross-encoder 对每条 query 的 20 个候选逐对前向推理，CPU 上无法线上使用。

可用性改造方向（未验证）：
- GPU 推理
- 只精排 top-5 而非 top-20（候选数与耗时近似线性）
- 仅对路由判定为复杂的查询启用（M3 的分流机制）

当前默认配置 `ENABLE_RERANK=false` 是正确的。

## 6. 无答案阈值校准：单一阈值不可行

M0 遗留问题是 `ANSWERABLE_MIN_RELEVANCE` 的初值 0.50 为拍定值。
本节的结论是：**问题不在于这个数字选得不对，而在于单一阈值机制本身不成立。**

### 无答案子集的构造

取真实 query，把其全部 gold 段落从检索结果中剔除，剩余的 top1 relevance
即"知识库无此知识点"时系统看到的分数。

不手写"知识库肯定没有"的问题：写的时候就知道答案不在库里，会不自觉写得
过于离题，识别率虚高，线上不成立。剔除 gold 的做法保留了 query 的真实性
与领域相关性，这才是线上的困难情形 —— 用户问了个合理问题，
但知识库恰好没覆盖。

### Top-1 relevance 分布（rrf，300 条有答案 / 299 条无答案）

| | min | p25 | median | p75 | max |
|---|---|---|---|---|---|
| 有答案 | 0.697 | 0.800 | 0.836 | 0.864 | 0.924 |
| 无答案 | 0.714 | 0.757 | 0.775 | 0.796 | 0.871 |

**无答案样本的最小值（0.714）高于有答案样本的最小值（0.697）。**
两个分布严重重叠，中位数仅差 0.061。

### 阈值扫描

| 阈值 | 无答案识别率 | 误拒率 |
|---|---|---|
| 0.30–0.65 | 0.000 | 0.000 |
| 0.70 | 0.000 | 0.003 |
| 0.75 | 0.191 | 0.057 |
| 0.80 | 0.799 | 0.257 |
| 0.85 | 0.977 | 0.617 |
| 0.90 | 1.000 | 0.983 |

0.70 以下全部漏判；0.75 识别率仅 19.1%；0.85 识别率 97.7% 但误拒 61.7%
—— 三分之二的可答问题被拒绝。在误拒率不超过 10% 的约束下，
最佳阈值是 0.75，但它只能识别不到两成的无答案查询。

`vector_bge` 上分布几乎相同（有答案 median 0.842 / 无答案 0.775），
确认这不是 RRF 引入的，而是稠密检索的固有性质：bge 归一化向量在
1.3 万段语料中总能找到"看起来有点像"的段落，relevance 天然聚集在
0.70–0.90 的窄带内。

### 结论与后续

单一 relevance 阈值不足以判定可答性。M3 应当引入独立的 answerability
判断，候选方向：

- 让 LLM 在生成前先判断"给定这些证据能否回答"（结构化输出）
- 用 top1 与 top2 的分数差（gap）而非绝对值 —— 真正命中时头部应更陡
- 引用校验前置：若答案句无法被任何 chunk 支持，则判定为无答案

阈值本身保留 0.75 作为粗筛（配置项已更新），但不作为唯一依据。

详细数据见 `docs/eval/threshold.md`。

### 附带发现：纯 BM25 方案的 relevance 全为 0

校准过程中发现 `bm25` variant 的全部 relevance 为 0.000，
而其 Recall@5 是 0.586（排序能力正常）。

根因是 `compute_relevance()` 只认 `rerank_logit` 与 `cosine_distance`，
BM25 结果两者皆无，故判定为"无信息"返回 0.0。这个 0.0 与
"计算得出确实不相关"无法区分，下游若照常比阈值会拒绝所有查询。

不给 BM25 编一个 [0,1] 映射 —— 它的分数是无界 TF-IDF 累加，
任何映射都会重新引入本项目要消除的那种不可解释量纲
（这正是用 RRF 而非归一化加权的理由）。
改为新增 `has_relevance_signal()` 显式区分两种 0.0，
无信息时退化为信任检索层排序，不做无依据的阈值判断。

## 7. 已知局限

1. **单一数据集**。T2Ranking 是通用搜索场景，结论不能直接外推到
   垂直领域知识库。垂直领域缺少「知识库 + 问答对 + 溯源 chunk」的
   闭环评测集（见 [ADR-002](../decisions/ADR-002-eval-dataset-choice.md)）。
2. **未按 query 类型分层**。T2Ranking 不提供类型标注，
   因此无法验证"BM25 在关键词类查询上更强"这一假设 ——
   这恰好是解释第 4 节负面结果所需的证据。
3. **抽样引入的偏差**。语料是 gold + 8 倍干扰的抽样，
   非全量 230 万段。干扰倍数会影响 Recall 绝对值
   （倍数越高越难），故本报告的数字只在方案间可比，
   不宜与其他论文的 T2Ranking 结果直接对照。
4. **延迟为单机 CPU 冷启后的稳态值**，未做多次重复取中位数。
   rerank 的 P50 与均值差距较大（9842 vs 11177），说明有长尾抖动。
5. **无答案子集是构造的**，非真实的"用户问了库里没有的问题"。
   剔除 gold 保留了 query 的领域相关性，但真实无答案查询的分布
   可能更分散（用户可能问完全跨领域的问题）。
6. **生成层指标尚未评测**（忠实度、答案正确性、引用准确率）。
